# Read-path audit, 2026-11-05

## Scope and pinned source

This audit covers `serialize.rs` at
`be2591509c68f828b43029a543ef9ffa290637b8` (`sprint/serialize-audit`).
It examines the runtime's existing read behavior against its vendored
`STANDARD.md` and `IMPLEMENTING.md`, including caller declarations, partial
consumption, scalar destinations, terminal refusal, and the public bit reader.
It does not import later strict-reader work or change the wire standard.

The runtime forbids unsafe code and has no library dependencies. The trust
boundary is `ReadStream`, not the unchecked `BitReader` building blocks.
An entry marked **bounded** below relies on the stated declaration and caller
boundary; it is not a claim about arbitrary application callbacks.
Source locations in this document name the pinned base unless stated otherwise.

## Findings

integration concern, not an assertion that ordinary `ReadStream` calls are

### sra-rs-1 — unchecked public bit-reader boundary

- **Location:** `src/bitpacker.rs:263`, `:319`, `:356`, `:408`, `:435`;
  exported by `src/lib.rs:124`.
- **Attacker effect:** if an application hands a truncated packet directly to
  `BitReader` and omits the documented logical-length preflight, fixed-width
  reads can assert in checked builds; release reads can interpret allocation
  slack or zero-filled missing bytes. Byte-slice reads can panic, and nonzero
  alignment returns false without poisoning subsequent core reads. These effects
  require bypassing the checked stream and violating the core caller contract.
- **Severity:** info. No path from a conforming `ReadStream` operation to these
  unchecked effects was found. The primitive is documented as unchecked and has
  no fallible return or first-error state; changing it would be an API decision.
- **Reduction:** keep packet ingress on `ReadStream`, including generated readers;
  do not treat `BitReader` as an alternate checked decoder. A future API card can
  make unchecked helpers private or change their signatures after auditing
  consumers. No new API or speculative runtime guard is introduced here.
- **Pin:** `tests/uniform.rs::u7_a_byte_count_past_the_buffer_refuses_at_initialization`,
  `tests/terminal.rs::failure_before_consumption_is_terminal`,
  `tests/format2.rs::bytes_past_the_stream_are_past_end`, and
  `tests/serialize.rs::test_read_bits_group` exercise the checked boundary and the
  valid core preconditions. The added
  `tests/hostile.rs::audit_checked_bits_do_not_read_nonzero_slack_as_packet_data`
  checks all widths 1..64 and bit offsets 0..7 at packet lengths 0..16 against
  both exact slices and nonzero slack; it compares accepted values with an
  independent bit-by-bit extraction. The existing `hostile_read` target receives
  `fuzz/corpus/hostile_read/audit-raw-u128-short`, `audit-group-248`, and
  `audit-group-256` for truncated wide reads and preflighted group edges. This is
  an open integration finding, not a fixed defect; no red-before/green-after
  claim is made.
- **Status:** open outside this card's no-public-API-change constraint.

## Arithmetic, allocation, and failure analysis

The checked reader carries a borrowed slice, a `u64` logical bit count, and a
`u64` position. There is no scratch buffer or refill state on reads. Bit windows
load at a byte index derived from position and mask only the requested bits.
The stream proves logical room before calling the core, so nonzero slack cannot
supply missing packet data. For addressable allocations on the tested target,
byte-to-bit conversion and the next <=32-bit request fit the bookkeeping width;
physically unallocatable multi-exabyte slices are not a tested capacity claim.

All ranged signed arithmetic moves into same-width unsigned wrapping arithmetic
before subtraction/reconstruction. Offsets are checked before assignment.
Fixed declarations are checked before shifts; the sealed storage set bounds
shifts to at most 127, and the i64 whole-unit difference is widened to i128.
All wide reads use at most four 32-bit groups. There is no input-sized integer
loop or input-selected runtime recursion.

The string reader is the only ordinary read path that grows a heap value.
It proves both the declaration bound and actual payload availability before
copying. A forged huge prefix over a short packet allocates nothing; a valid
large payload can still cause allocation proportional to its declared and
received length. Application packet size, aggregate allocation budgets, and
allocation failure policy remain outside this runtime. The core has no JSON
parser, so JSON depth, duplicate keys, numeric lexemes, and escapes have no
runtime reachability here. Object callbacks can recurse or allocate by their
own implementation; the stream cannot bound those application choices.

Primitive scalar destinations change only on success. A multi-group failure
may consume earlier groups; string validation can consume its payload before
refusing. The recorded position is therefore evidence of progress, never a
restart offset after failure. Composite objects may retain earlier accepted
members. Every later stream read, including zero-bit operations and objects,
refuses with the first error without further consumption. A clone taken before
failure is an independent snapshot; a clone after failure carries the latch.

Raw floats refuse all non-finite exponent patterns before conversion and retain
negative zero/subnormals exactly. Compressed arithmetic is float32 and finite
checked after decode. Its legal upper decode is `min + delta`, which may exceed
`max` because `delta` rounded; adding a clamp would violate the pinned standard.
The finite-decode check also refuses a non-finite precomputed `min` without
publishing a scalar result. Invalid precomputed widths/maxima/deltas refuse as
`ValueOutOfRange` before reading any bits.

## Added audit witnesses

The existing unit and fuzz harnesses are extended rather than forked. The new
unit test checks the logical packet boundary independently of the core window
implementation. The existing fuzz target retains its previous operations and
adds the precomputed entry point, bad declarations, zero-bit/wide fixed forms,
object callback refusals, and preflighted core groups. Its post-refusal checks
now require the exact first reason and also exercise a zero-bit read and end.
